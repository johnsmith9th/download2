================================================================================
Download2 v0.1.0 - THIRD-PARTY COMPONENT NOTICES
================================================================================

Hand-maintained file. Add a section here when vendor/modules.txt gains a module.
The in-app list (panel > About > Acknowledgements, frontend/index.html) names the same
components one line each; this file is that list's distribution-compliance superset,
so it goes down to the verbatim text of every license.

What is covered here:
      7  Go modules linked into download2.exe (windows/amd64)        - SECTION A
      2  Go modules vendored but not linked by the windows build     - SECTION A, 'Linked : no'
      2  build and run-time components, one of them link-only        - SECTION B
  10 sections carry the verbatim license text, 1 is link-only by design (see its Note), 0 unbundled.

Why the transitive modules are here at all: BSD-3-Clause requires a copy of the license to
accompany distribution, and a statically linked transitive Go module counts as distributed
just as much as a direct requirement does. Six of the nine vendored modules are not direct
requirements in go.mod - they arrive through Wails v3, and four of those are linked in.

Every text below is a verbatim copy of a file shipped by that component's own authors, taken
from the exact version in ./vendor (for the Go toolchain: the local GOROOT this product was
built with). Where a component states a license identifier in two places (in-app declaration,
package metadata) and the text reads differently, the text governs.

Re-check the linked set after any dependency change with:
    GOOS=windows GOARCH=amd64 go list -deps ./... | grep <module path>
A hit means it is in the binary; no hit means the section below is acknowledgement only.

--------------------------------------------------------------------------------
SECTION A - GO MODULES VENDORED UNDER ./vendor
--------------------------------------------------------------------------------

Every 'Linked : yes' module is statically linked into the executable for windows/amd64,
direct or transitive. A 'Linked : no' section names one that vendor/ carries and go.mod
requires, while the windows build reaches no package of it - so not a byte of it is in
download2.exe, and its text is bundled anyway because vendor/ is the manifest here.

toolchain that produces the exe and the runtime the exe needs on the host. No font is
bundled either: the interface asks Windows for Segoe UI and Microsoft YaHei, and ships
no glyph data of its own.
